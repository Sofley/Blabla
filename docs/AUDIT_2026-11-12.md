## 2. Найденные ошибки и слабые места (с предложением решения)

1. **Лимит 20 МБ на документ** противоречит п. 17.6. Решение: убрать лимит, предупреждать только о нехватке места.
2. **Резервная копия собирается целиком в памяти** (все документы в base64 внутри одного JSON).
   При сотнях МБ документов возможен вылет приложения на слабом телефоне. Решение: новый формат копии —
   зашифрованный архив с потоковой записью. Последствие: формат копии меняется; старые копии 3.0 и 2.x
   продолжают читаться.
3. **Временные файлы при «Поделиться»/открытии документа** удаляются через 2 минуты, но если приложение
   закрыть раньше, расшифрованная копия остаётся в кэше. Решение: чистить кэш при каждом запуске.
4. **Данные виджета не зашифрованы** (иначе система не сможет нарисовать виджет). Решение уже есть —
   переключатель «Скрыть суммы в виджете»; можно сделать его включённым по умолчанию — на ваше решение.
5. **Нет внутреннего номера электронной сделки.** Сейчас «номер сделки» — это номера контрактов №1/№2.
   Для раздела 16 нужен отдельный номер. См. вопрос 4.
6. **Роли без сервера** работают только на одном устройстве — это ограничение архитектуры, не ошибка.
7. Переводы uz / sr / zh сделаны ИИ — нужна вычитка носителем.
8. Плагин `home_widget` использует устаревший способ подключения Kotlin — сейчас собирается,
   в будущих версиях Flutter потребует обновления плагина.
9. Проверка на реальном телефоне в этой среде невозможна (нет эмулятора): установка, обновление,
   виджет, уведомления, Google Drive — проверяете вы по списку из раздела 6.

## 3. Что потребуется для разделов 16–17 (документы)

Модель (новая, офлайн, без платных сервисов):
- **Документ сделки**: категория (Основной договор / Invoice / Приложение / Доп. соглашение / Корректировка / Прочее),
  номер, дата документа, статус (Действующий / Заменённый / Аннулированный), связь с версией основного договора.
- **Версия файла**: имя, формат, размер, дата загрузки, кто загрузил; замена создаёт новую версию,
  старая сохраняется со статусом «Заменённый».
- **Блок «ОФИЦИАЛЬНЫЙ КОНТРАКТ»**: номер, дата, клиент, номер электронной сделки, файлы, статус «прикреплён / не прикреплён»,
  кнопки просмотр / скачать / добавить / заменить.
- Форматы: PDF, DOC, DOCX, XLS, XLSX, JPG, JPEG, PNG; просмотр внутри приложения — изображения и PDF;
  DOC/DOCX/XLS/XLSX — через установленное приложение телефона.
- Поиск сделок по номерам договора, Invoice, доп. соглашений и названию документа.

Миграция: существующие документы 3.0 (их нет у пользователей — 3.0 ещё не выпускалась, но в коде предусмотрим)
переходят в категорию «Прочие», статус «Действующий», версия 1. Файлы не перемещаются и не перешифровываются.
